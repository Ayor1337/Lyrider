# 桌面歌词设计参考

核对日期：2026-10-07。

## 参考软件的做法

MusicPlayer2 的桌面双行歌词显示当前句和下一句，自动对齐时分居左右两端。官方设置页分别提供文字颜色、高亮颜色和一个桌面歌词字体设置。[官方歌词设置说明](https://github.com/zhongyang219/MusicPlayer2/wiki/%E6%AD%8C%E8%AF%8D%E8%AE%BE%E7%BD%AE)

其 `DrawLyricsDoubleLine` 用同一个字体测量两句，当前句请求高亮，下一句不高亮。`DrawHighlightLyrics` 只在卡拉 OK 开启时按进度裁剪高亮区域，关闭后绘制整句高亮；该函数在进度为 0 或达到 1000 时直接返回。译文在另一个绘制路径使用缩小字号，因此“两句原文等字号”与“译文等字号”需要分别判断。[双行与高亮源码](https://github.com/zhongyang219/MusicPlayer2/blob/22ab2566c74b3dc494d442e6d6a5d32604a52af6/MusicPlayer2/LyricsWindow.cpp#L242-L436)

Lyricify 4 的官方配置将双行、单行和卡拉 OK 颜色分开：`duo_line_style` 默认第一种填充为 `MainColor`、第二种为 `White`，两者都采用黑色边框；`is_duo_line` 和 `is_karaoke` 是独立开关。配置中还有桌面歌词字体和对齐设置。这支持将双行颜色区分与逐字扫色分别处理，但配置文件本身不能证明每个运行状态的渲染细节。[官方配置及注释](https://github.com/WXRIW/Lyricify-App/blob/3cc862a107b8eb9d6588ac90130822c7d4886037/docs/Lyricify%204/settings.json#L98-L140)

## Lyrider 采用的行为

以下是结合本项目现有交互和用户要求作出的选择，不代表所有桌面歌词软件的统一规范。

- 普通逐句模式：当前句整句使用高亮颜色，译文或下一句使用文字颜色。
- 卡拉 OK 模式：有有效逐字时间时，用真实演唱时间从文字颜色扫到高亮颜色；缺少逐字时间时，当前句整句高亮。
- 两个歌词区域始终使用相同字号，包括第二行显示译文的情况。保留黑色描边。
- 保留上下排列和错位排列。两种排列的行距随窗口高度适度增减，额外高度的 20% 用于行距；歌词整体在窗口内垂直居中；错位排列保留内边距，单行模式和歌名保持左对齐。
- 双行原文按过滤署名和间奏后的歌词序号轮流占用两个位置。当前句留在预览时的位置，已唱完的位置换成新的下一句；高亮和真实逐字扫色随活动位置移动。重复文本、暂停刷新和跳转都按时间轴序号处理，最后一句保留原位；原文加翻译仍按固定上下顺序显示。
- 前奏或没有同步歌词时显示歌曲信息：双行为歌名加“歌手 · 专辑”，单行为“歌名 - 歌手”，都使用文字颜色。有逐字时间的间奏预览仍按真实时间推进，不估算扫色进度。
- 字体可自选，缺字时回退到 Segoe UI 和系统复合字体。渲染语言按歌曲决定：日文歌词（至少五分之一行含假名）用日文字形，中文歌词和译文用简体中文字形，其余跟随界面语言。
- 竖排时中日文标点换成 Unicode 竖排字形（句读号落在字格右上角、括号转为竖向），长音符“ー”、波浪号和连字符随拉丁文字旋转 90°。
- 每秒刷新只移动逐字时间锚点时不重排窗口，只更新扫色；扫色随渲染帧推进。

解锁时四边和四角都可拖动缩放，由系统缩放循环处理，拖动跟手。拖动的边停在显示器工作区边缘，宽度限制在 320–1200、高度在内容所需高度与 480 之间（逻辑像素）。只拖左右边时，自动高度随换行变化、底边保持不动；拖上下边会改为保存手动高度，双击上下边恢复自动高度。背景铺满整个窗口（8px 圆角），与缩放边框的触发范围一致。鼠标停在边上时，该边中点淡入一枚白色小药丸；停在角上时，只在该角淡入一段与背景圆角同心的圆弧。指示器显示时淡入并略带回弹地放大，隐藏时淡出缩回，拖动期间保持显示；悬停背景和工具栏的出现与消失采用相同节奏（160ms 减速淡入、200ms 加速淡出，不回弹）；工具栏淡出期间不响应点击。锁定与解锁切换时背景和工具栏同样渐变，鼠标穿透在锁定时立即生效。系统关闭动画时都直接切换。

锁定时隐藏背景，主体继续鼠标穿透；悬停仅显示可点击的解锁图标（白色圆底配深色图标的反色圆形按钮，带淡描边以便在浅色桌面上辨认），鼠标移入时淡入、移开时淡出，节奏与悬停背景一致；歌词窗口隐藏时图标立即隐藏。托盘解锁入口保留。

文字颜色和高亮颜色继续允许分别设置；使用者若选为同一种颜色，两句自然不会形成颜色差异。
